# 평가 러너와 AI 설정

## 실행

```
go run ./cmd/eval --provider mock        # CI·make verify. 결정적, 네트워크 없음
go run ./cmd/eval --provider anthropic   # 수동. 키가 없으면 건너뛰고 종료 코드 0
```

종료 코드: 0 합격(또는 키 없음으로 건너뜀), 1 기준 미달 또는 회귀, 2 설정 오류.

## 회귀 감지와 이력

- 기준선은 저장소에 커밋된 `evals/baseline.json`(케이스별 통과 여부)이고 바이너리에도 내장되어 CI 와 로컬이 같은 파일과 비교한다.
  기준선에서 통과하던 케이스, 또는 기준선에 없던 새 케이스가 실패하면 합격률이 기준을 넘어도 종료 코드 1 이다.
  기준선에서 사라진 케이스는 경고만 출력한다. mock 이 아닌 공급자는 `--baseline <파일>` 을 줄 때만 비교한다.
- 기본 실행은 비교만 한다(파일·DB 를 쓰지 않는다). 골든셋을 바꾼 뒤 저장소 루트에서 `go run ./cmd/eval --provider mock --update-baseline`
  으로 기준선을 갱신해 함께 커밋한다(합격한 결과만 저장되고 `--only` 와는 함께 쓸 수 없다).
- `--db <SQLite 파일>` 을 주면 실행 이력(시각·공급자·모델·합격률·새로 실패/통과·케이스별 결과)을 `eval_runs` 에 저장하고
  감사 로그 `eval.run` 을 남긴다. 관리자·감사(`eval:read`)가 "평가 이력" 화면에서 본다. `make verify` 4단계는 `--db` 를 쓰지 않는다.
합격 기준은 `evals/evals.go` 의 상수다: 문서 판정 90%, 견적서 추출 90%(케이스 수 하한 10), 도구 선택 90%, 케이스 수 하한(문서 20, 도구 선택은 전체의 90%라서 지금 81),
그리고 `critical`(문서 안 지시문. 문서 판정·규정 검색·도구 선택 모두 가질 수 있다) 케이스는 하나라도 틀리면 불합격.

자동 매입 전표 골든셋(`journals.json`, 12건, B31)은 틀과 구조 검증(`evals/journals_test.go`)까지 있고, 실제 파이프라인 채점(`journals` 묶음)은 전표 서비스가 나온 뒤 평가 하니스에 연결한다. 연결 전에는 합격 기준에 포함되지 않는다.

mock 공급자는 규칙 기반이라 "파이프라인(마스킹·스키마 검증·코드 판정·권한)"을 잰다. 모델 품질은 anthropic 수동 실행으로 잰다.

## 설정(환경변수)

| 이름 | 뜻 |
|---|---|
| `PL_LLM_PROVIDER` | `mock`(기본) 또는 `anthropic` |
| `PL_LLM_MODEL` | 모델 ID. 코드에 기본값이 없다. anthropic 이면 필수. 권장 시작값 `claude-haiku-5-5`(claude-api 스킬 2026-11-03 표 기준), 정밀도가 필요하면 `claude-sonnet-5-5` |
| `PL_LLM_API_KEY_ENV` | 키를 읽을 환경변수 이름(기본 `ANTHROPIC_API_KEY`). 키 자체는 커밋하지 않는다 |
| `PL_LLM_PRICE_IN_MICRO_PER_MTOK`, `PL_LLM_PRICE_OUT_MICRO_PER_MTOK` | 1백만 토큰당 가격(1e-6 USD). 비면 비용 0 으로 기록 |

모델 허용 목록·일일 한도는 DB(`llm_model_policies`, `llm_daily_quotas`)이며 AI 사용량 화면에서 관리한다.
정책 규칙이 하나도 없으면 모든 호출이 거부되고, 서버 기동 시 규칙이 비어 있으면 기본 모델 하나만 허용하는 규칙이 들어간다.

## 한계

- 이미지 증빙은 원문 텍스트가 없어 마스킹과 "추출값이 원문에 있는지" 교차 확인이 적용되지 않고, 이미지 그대로 AI 로 전달된다. 텍스트·PDF 텍스트 경로만 마스킹과 교차 확인을 받는다.
- mock 은 규칙 기반이라 모델 품질을 재지 못한다. 숫자를 지어내는 모델(`합계보정`·`단가보정` 케이스)은 mock 이 흉내 내고 코드의 교차 확인이 걸러내는지만 본다.
