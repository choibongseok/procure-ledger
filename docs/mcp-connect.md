# AI 도구(Claude Code·Claude Desktop)에 ERP 연결하기

`erp-mcp` 는 ERP 기능을 MCP 도구로 내보냅니다. 호출자는 개인 토큰으로 식별되고, 웹 화면과 같은 권한 표와 같은 서비스 계층을 지나며, 모든 호출이 감사 로그(경로 "AI 도구")에 남습니다. 권한이 없는 도구 호출은 거부되고 그 거부도 기록됩니다.

연결 방법은 두 가지입니다.

| 방법 | 쓰는 때 | 접속 주소·실행 |
|---|---|---|
| 서버의 HTTP 엔드포인트 | 서버가 이미 떠 있을 때(권장) | `POST http://<서버>/mcp`, 호출마다 `Authorization: Bearer <토큰>` |
| `erp-mcp` stdio | 클라이언트가 프로세스를 직접 띄울 때 | `bin/erp-mcp --transport stdio`, 환경변수 `PL_MCP_TOKEN` |

`erp-mcp --transport http --addr :8090` 으로 MCP 전용 HTTP 서버를 따로 띄울 수도 있습니다. 서버 바이너리의 `/mcp` 와 같은 핸들러입니다.

## 1. 토큰 발급 순서

1. 서버를 띄웁니다(README 의 "5분 실행").
2. 연결할 사람의 계정으로 로그인합니다. AI 는 이 사람의 권한으로만 움직입니다. 예를 들어 `staff@pl.test`(직원)로 발급한 토큰은 결재 도구(`approve_or_reject`)를 쓸 수 없습니다.
3. 왼쪽 메뉴 "개인 토큰"에서 이름과 유효 기간(1~365일, 기본 30일)을 정하고 "발급"을 누릅니다.
4. 화면에 나온 토큰(`plp_` 로 시작)을 복사합니다. **이 화면을 닫으면 다시 볼 수 없습니다.** 서버에는 해시만 저장됩니다. 잃어버리면 폐기하고 새로 발급합니다.
5. 토큰은 비밀번호처럼 다룹니다. 설정 파일을 저장소에 커밋하지 않습니다. 아래 예시의 `<토큰>` 자리에는 실제 값을 넣습니다.

토큰으로는 토큰을 발급하거나 폐기할 수 없습니다. 이 두 동작은 로그인 세션(화면)에서만 됩니다.

### 토큰 개수 상한

사용자당 사용 중인 토큰(폐기·만료되지 않은 것)은 `PL_MAX_ACTIVE_TOKENS` 개까지입니다. 기본값은 10이고 0 이면 제한이 없습니다. 상한에서 발급하면 "사용 중인 개인 토큰이 상한(N개)에 도달했습니다. 쓰지 않는 토큰을 폐기한 뒤 다시 발급하세요." 라는 안내가 나옵니다. 쓰지 않는 토큰을 폐기하면 다시 발급할 수 있습니다.

## 2. Claude Code

서버 HTTP 엔드포인트로 붙입니다. 서버 주소가 `http://localhost:8080` 인 경우입니다.

```
claude mcp add --transport http procure-ledger http://localhost:8080/mcp --header "Authorization: Bearer <토큰>"
```

stdio 로 붙이려면 `erp-mcp` 의 절대 경로와 서버가 쓰는 DB 파일의 절대 경로를 넘깁니다.

```
claude mcp add procure-ledger -e PL_MCP_TOKEN=<토큰> -e PL_DB_PATH=/절대/경로/data/erp.db -- /절대/경로/bin/erp-mcp --transport stdio
```

`claude mcp add` 의 옵션 형식은 설치된 `claude mcp add --help` 로 확인했습니다. 연결된 뒤 Claude Code 에서 `/mcp` 로 상태를 볼 수 있습니다.

## 3. Claude Desktop

`claude_desktop_config.json` 의 `mcpServers` 에 stdio 서버로 넣습니다. Claude Desktop 은 프로세스를 직접 띄우므로 stdio 방식입니다.

```json
{
  "mcpServers": {
    "procure-ledger": {
      "command": "/절대/경로/bin/erp-mcp",
      "args": ["--transport", "stdio"],
      "env": {
        "PL_MCP_TOKEN": "<토큰>",
        "PL_DB_PATH": "/절대/경로/data/erp.db"
      }
    }
  }
}
```

설정을 저장한 뒤 Claude Desktop 을 다시 시작합니다. 이 저장소의 검증은 서버·`erp-mcp` 쪽 동작까지이고, Claude Code·Claude Desktop 프로그램에 실제로 붙여 보는 것은 하지 않았습니다. 설정 형식은 각 제품의 문서를 따릅니다.

## 3-1. 직접 호출해 보기(확인용)

토큰이 있으면 클라이언트 없이도 호출해 볼 수 있습니다.

```
curl -sS -X POST http://localhost:8080/mcp \
  -H "Authorization: Bearer <토큰>" -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
```

토큰 없이 부르면 401 입니다. 직원 토큰으로 `approve_or_reject` 를 부르면 `isError: true` 와 "권한이 없습니다" 문구가 돌아오고, 이 거부가 감사 로그에 남습니다.

## 4. 도구와 필요한 권한

도구는 19개입니다. 모델은 이름과 설명문만 보고 고르므로 설명문에 "이럴 때는 다른 도구"가 적혀 있습니다. 조직 도구 `search_people`·`get_org_unit`·`who_approves` 는 연락처(이메일·휴대전화)와 사번을 돌려주지 않습니다.

## 5. 호출 한도

AI 연결은 분당 호출 수를 제한할 수 있습니다. 서버와 `erp-mcp` 는 같은 환경변수를 읽습니다.

| 이름 | 뜻 | 기본 |
|---|---|---|
| `PL_MCP_RATE_PER_MIN` | 토큰 하나의 분당 호출 한도 | 0(꺼짐) |
| `PL_MCP_RATE_PER_USER_PER_MIN` | 한 사용자의 모든 토큰을 합친 분당 호출 한도 | 0(꺼짐) |

- 두 값이 **모두 0 이면 한도가 꺼진 채로 동작**하고, `erp-mcp` 는 기동할 때 stderr 에 경고만 냅니다(stdout 은 프로토콜 채널이라 쓰지 않습니다). 호출 폭주를 막으려면 둘 중 하나 이상을 설정합니다.
- 한도는 DB 로 셉니다. 서버(`/mcp`)와 `erp-mcp` 가 같은 DB 파일을 쓰면 한도가 합쳐서 적용됩니다. 그래서 `erp-mcp` 도 서버와 같은 `PL_DB_PATH` 와 같은 한도 값으로 실행해야 합니다.
- 한도를 넘은 호출은 거부되고 감사 로그에 남습니다. 같은 토큰이 같은 분에 여러 번 거부되면 첫 거부만 바로 기록하고, 그 분이 지난 뒤 2회 이상이었을 때 횟수 요약 한 줄을 더 남깁니다. 기존 기록은 고치지 않습니다.
- "AI 연결 사용 현황" 화면(감사·관리자)에서 도구별·토큰별 호출 수와 거부를 볼 수 있습니다.

## 6. 토큰을 폐기하면

- 토큰을 폐기하거나 만료되면 **다음 호출부터** 거부됩니다. HTTP 는 401 입니다.
- stdio 로 이미 열려 있는 세션은 프로세스가 계속 떠 있습니다. 폐기해도 연결이 끊기지는 않지만, 도구를 호출할 때마다 토큰을 다시 검증하므로 그 호출부터 "인증이 필요합니다: 토큰이 더 이상 유효하지 않습니다" 오류가 돌아옵니다. 폐기 직전까지 받은 결과는 클라이언트가 이미 가지고 있습니다.
- 소유자의 역할이 바뀌거나 계정이 비활성화되어도 같은 방식으로 다음 호출부터 반영됩니다.
- 이미 폐기된 토큰으로 `erp-mcp` 를 새로 띄우면 기동 단계에서 "토큰 인증 실패"로 끝납니다.

## 7. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 401 | 토큰이 틀렸거나 폐기·만료됨. `Authorization: Bearer ` 접두를 확인 |
| "권한이 없습니다" | 토큰 소유자의 역할에 그 도구의 권한이 없음. 감사 로그에 거부로 남음 |
| `erp-mcp` 가 바로 종료 | `PL_MCP_TOKEN` 이 비었거나 유효하지 않음, `PL_DB_PATH` 가 서버와 다른 파일 |
| 한도 경고가 나옴 | 위 5절. 한도를 켜지 않아도 동작은 합니다 |
| 발급할 때 상한 안내 | 위 1절의 토큰 개수 상한 |
