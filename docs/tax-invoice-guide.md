# 전자세금계산서 운영 가이드

전자세금계산서를 발행하고 받는 연계 대행사(ASP)를 ProcureLedger 에 연결하고 운영하는 관리자를 위한 문서입니다. 기능의 정본은 해당 기능 명세 입니다. 이 저장소에는 **대행사 연결 규칙(인터페이스)과 시험용 모의 대행사**만 있고, 실제 대행사의 어댑터와 계약은 도입하는 회사가 마련합니다.

## 1. 시작하기 전에

| 준비 | 내용 |
|---|---|
| 대행사 계약 | 국세청 연계 대행사와 계약하고 접속 주소(엔드포인트)와 API 키를 받습니다. 서명을 대행사가 대신해 주는 방식(서버는 API 키만 보관)을 기준으로 시험합니다. 서버가 인증서로 직접 서명하는 방식을 쓰는 어댑터를 위해 인증서 보관 칸이 있습니다 |
| 어댑터 | 대행사 규격과 ProcureLedger 사이를 잇는 어댑터는 회사가 만들어 서버에 등록합니다. 어댑터는 이 저장소의 적합성 시험 키트(`taxasp.Conformance`)를 통과해야 합니다(멱등 발행, 수신 목록 쪽 나누기, 오류 분류, 응답 본문 비노출) |
| 회사 정보 | 관리 > 회사 설정에 **사업자번호·대표자**를 먼저 입력합니다. 비어 있으면 매출 발행은 거부되고 매입 동기화는 시작하지 않습니다 |
| 키 | 서버 환경에 `PL_ACCOUNT_SECRET_KEY` 가 있어야 대행사 키와 인증서를 저장할 수 있습니다(저장할 때 이 키로 봉인합니다). 모의 대행사는 비밀이 없어 키 없이도 됩니다 |

## 2. 대행사 연결 설정

관리 > **전자세금계산서 대행사**(`/admin/tax-asp`) 화면입니다. 관리자(`taxasp:manage`)만 열 수 있고, **로그인한 화면에서만** 바꿀 수 있습니다(개인 토큰·API 토큰으로는 안 됩니다). 이 권한은 위험 권한이라 부여할 때 두 사람 확인을 거칩니다.

1. **대행사**를 고르고 접속 주소(https)와 API 키를 입력한 뒤 저장합니다.
2. 저장하면 키·인증서·비밀번호·주소는 봉인되어 다시 볼 수 없습니다. 화면에는 접속 **호스트**, 키 등록 여부, 인증서 만료일과 주체 끝 부분만 보입니다. 바꾸려면 새 값을 입력합니다(칸을 비우면 저장된 값을 그대로 씁니다).
3. **시험 연결**로 결과를 확인합니다. 결과는 한국어 문장이고 대행사의 응답 본문은 화면·기록 어디에도 남지 않습니다.
4. **사용 켜기**를 누르면 발행(전송)이 시작됩니다. 끄면 발행 단추가 막히고 작성은 계속 됩니다. 수기 등록·대조는 대행사 없이도 됩니다.

접속 호스트는 **처음 저장한 호스트 하나로 고정**됩니다. 다른 호스트로 바꾸려면 설정을 다시 저장해야 하고, 바뀐 사실은 감사 로그(`taxasp.host_set`)에 남습니다. 주소는 https·표준 포트·호스트 이름만 허용하고(IP 주소·내부 주소·사용자 정보 불가), 연결 직전에도 내부 주소로 향하는지 한 번 더 검사하며 리다이렉트는 따라가지 않습니다.

## 3. 인증서 등록과 만료 대응

- 인증서(PEM)와 개인키(PEM)를 함께 입력하면 서버가 **짝이 맞는지** 검사하고 만료일과 주체를 읽습니다. 암호화된 개인키는 비밀번호 칸에 비밀번호를 함께 입력합니다.
- **만료일은 평문 날짜**로 저장되어 알림과 점검표가 키를 풀지 않고 읽습니다.
- 만료 **30일 전, 7일 전, 당일**에 관리자(`taxasp:manage` 보유자)에게 "대행사 인증서 만료 임박" 알림이 갑니다(필수 알림이라 끌 수 없습니다). 같은 인증서의 같은 시점은 한 번만 알립니다.
- 만료되면 **세금계산서 발행이 거부**되고(사용 켜기도 거부됩니다) 도입 점검표 "전자세금계산서 연동" 항목이 미완료가 됩니다. 이미 전송 중인 건은 어댑터가 판단합니다. 수기 등록과 대조는 영향이 없습니다.
- **교체 절차**: 새 인증서를 대행사에서 받아 설정 화면에 인증서와 개인키를 입력해 저장하고, 시험 연결로 확인합니다. 만료일이 바뀌면 알림 기록이 새 인증서 기준으로 다시 시작합니다. 만료 7일 전에는 끝내는 것을 권합니다.

## 4. 키 교체

계좌 키(`PL_ACCOUNT_SECRET_KEY`) 교체는 대행사 설정의 봉인 덩어리도 함께 다시 봉하므로 **대행사 설정을 다시 입력할 필요가 없습니다.** 절차는 [운영 문서의 키 관리](operations.md)를 따릅니다. 교체 뒤에는 설정 화면에서 **시험 연결**을 한 번 눌러 확인합니다. 키를 잃으면 저장된 대행사 정보를 풀 수 없으니(화면에 "저장된 대행사 정보를 풀 수 없습니다" 안내) 설정을 다시 저장합니다.

## 5. 모의 대행사와 운영 경고

모의 대행사("모의 대행사(시험용)")는 결정적으로 동작하는 시험·시연용 대행사입니다. **실제 국세청에는 접수되지 않습니다.**

- 개발 모드(`PL_DEV_IDP` 켜짐)에서는 경고 없이 쓸 수 있습니다.
- **운영(`PL_DEV_IDP` 꺼짐)에서 모의 대행사를 고르면** 설정 화면에 경고 배너가 뜨고 도입 점검표가 미완료가 됩니다(모의가 켜진 채 발행되는 사고를 막기 위해서입니다). 실제 대행사를 설정한 뒤 모의는 쓰지 않습니다.
- 모의 시나리오는 개발·시험 환경의 설정 값 `taxasp.mock_mode` 로 고릅니다: `none`(기본), `transient`(처음 몇 번 일시 오류), `permanent`(검증 반려), `delayed`(접수 지연), `conflict`(같은 승인번호 다른 내용). 운영에서 바꾸지 않습니다.

## 6. 복구 리허설과 로컬 시험

- `PL_REHEARSAL` 로 띄운 복구 리허설 서버는 대행사 호출·동기화·재시도를 하지 않습니다(복구본이 운영 대행사에 이중 발행하는 사고를 막습니다). 설정 화면은 읽기만 되고 변경·시험 연결·켜기가 막힙니다.
- 로컬 시험 서버에 대행사 흉내 서버(루프백 주소)를 연결하려면 `PL_NOTIFY_INSECURE_LOCAL` 을 켭니다. **운영에서는 켜지 않습니다.**

## 7. 권한과 권한 분리

| 권한 | 할 수 있는 일 | 기본 역할 |
|---|---|---|
| `taxinvoice:read` | 세금계산서 목록·상세·조회 | 재무·관리자·감사 |
| `taxinvoice:write` | 매출 작성·수정·취소, 매입 수기 등록·등록 취소 | 재무 |
| `taxinvoice:issue` | 매출 **발행**(전송 요청)·다시 전송 | 재무 |
| `taxasp:manage` | 대행사 설정·키·인증서·시험 연결·켜기/끄기 | 관리자(위험 권한, 세션 전용) |

권한 분리(관리 > 권한 분리 규칙)에서 두 규칙이 관련됩니다.
- `tax.create_issue`: 매출 세금계산서를 **작성한 사람이 발행까지** 하면 위반입니다(법적 증빙을 혼자 만들고 내보내는 것을 막습니다). 기본은 경고이고 회사 설정에서 차단으로 바꿀 수 있습니다.
- `hold.taxasp_issue`: **대행사 설정(`taxasp:manage`)과 발행(`taxinvoice:issue`) 권한을 한 사람이 함께 가지면** 위반입니다(인증서를 관리하는 사람이 발행도 하는 것을 막습니다). 기본은 경고입니다. 기본 역할에는 이 쌍이 없고, 사용자 정의 역할로 합칠 때만 생깁니다.

## 8. 알림

| 알림 | 받는 사람 | 메일 기본 |
|---|---|---|
| 세금계산서 전송 실패 | 발행 권한 보유자 | 켜짐 |
| 세금계산서 수신 요약 | 작성 권한 보유자 | 꺼짐 |
| 대행사 인증서 만료 임박 | 대행사 설정 권한 보유자 | 켜짐(필수) |

알림 본문에는 건수·종류·앱 링크만 있고 금액·거래처·번호·사업자번호는 없습니다.

## 8.1 자동 매입 전표(선택, 기본 꺼짐)

수신 세금계산서를 입고와 연결(확정)할 때 매입 전표를 자동으로 만들게 할 수 있습니다. 설정 화면은 없고 설정 값 `app_settings` 의 키 `taxinvoice.auto_journal` 을 `on` 으로 두면 켜지고, 키가 없거나 `off` 면 꺼져 있습니다(예: `INSERT INTO app_settings (key, value, updated_at) VALUES ('taxinvoice.auto_journal', 'on', '<UTC 시각>') ON CONFLICT (key) DO UPDATE SET value = excluded.value`). 켜면 전표가 없는 입고마다 임시 전표가 한 번만 생기고 승인은 일반 전표 절차(승인 요청 → 결재, 권한 분리)를 탑니다. 월 마감·계정 규칙 누락 등으로 만들 수 없으면 전표 없이 확정되고, 확정 화면과 대조 목록에 사유 한 줄이 나오니 전표를 직접 작성해 연결하세요.

## 9. 문제 해결

화면에 보이는 사유 문장과 조치입니다.

| 사유(화면 문장) | 조치 |
|---|---|
| 대행사에 연결하지 못했습니다. | 네트워크·접속 주소를 확인합니다. 자동으로 다시 시도합니다 |
| 대행사 응답이 늦어 중단했습니다. | 대행사 장애 여부를 확인합니다. 자동으로 다시 시도합니다 |
| 대행사가 일시적으로 처리하지 못했습니다. | 자동으로 다시 시도합니다 |
| 대행사 인증에 실패했습니다. 대행사 설정을 확인하세요. | API 키·인증서가 맞는지 설정 화면에서 다시 저장하고 시험 연결합니다 |
| 대행사 인증서가 만료되었습니다. | 3절의 교체 절차를 따릅니다 |
| 대행사가 내용 검증에서 반려했습니다. | 내용을 고쳐야 하므로 건을 취소하고 새로 작성합니다 |
| 대행사에 이미 접수된 건입니다. | 대행사 쪽 접수 상태를 확인합니다 |
| 대행사 호출 한도를 넘었습니다. | 다음 주기에 다시 시도합니다 |
| 대행사 또는 국세청이 반려했습니다. | 반려 사유를 대행사에서 확인하고 새로 작성합니다 |
| 재시도 횟수를 넘어 중단했습니다. | 원인을 해결한 뒤 "다시 전송"(건당 5번까지) 하거나 포기합니다 |
| 국세청 수신 확인이 오래 걸려 중단했습니다. | 대행사에서 접수 상태를 확인합니다 |
| 이미 등록된 승인번호입니다. | 같은 승인번호는 한 번만 등록됩니다. 기존 건을 확인합니다 |
| 대행사 설정이 없거나 꺼져 있습니다. | 2절의 설정과 사용 켜기를 확인합니다 |
| 복구 리허설 중에는 대행사 호출을 하지 않습니다. | 리허설 서버에서는 정상입니다 |
| 내부 오류로 중단했습니다. | 감사 로그와 서버 로그를 확인하고 관리자에게 알립니다 |
| 아직 국세청 수신 전입니다. | 접수 확인을 기다립니다(자동으로 조회합니다) |
| 처리되었습니다. | 정상입니다 |
